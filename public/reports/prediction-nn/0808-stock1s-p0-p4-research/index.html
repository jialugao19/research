关键指标总览

P0：去除全天 coverage future information

实验目的

P0 解决 candidate universe 是否使用了 signal timestamp 之后才能知道的 full-day data quality。旧口径可能让模型学习 E[r | X_t, 未来全天数据正常, 未来成交存在]，而不是部署需要的 E[r | X_t]。

实验方案

采用同预算 retrain/control：P0-T 使用 point_in_time_index_union + pit_annotate，full-day coverage 只做 annotation；P0-LR 使用 legacy full_day_filter。两臂固定模型、target、loss、seed、训练预算、checkpoint selection 和 full val/test eval。

实验过程

先比较 candidate keys 与 endpoint keys，再训练/评估。legacy candidate keys 是 PIT candidate keys 的严格子集；PIT-only candidates 为 train 10,132、val 1,788、test 1,192；endpoint keys 在三个 split 上完全一致。

P1：Label validity 与 score 相关

实验目的

P1 区分真实不可执行与数据工程 censoring，避免模型把数据源质量学成交易信号。真实不可执行可以进入部署目标；data-censored row 不能当成 execution-negative。

实验方案

方案 A 为 censor-aware validity head：保留 return_zscore、execution_valid_target、return_mask、label_data_valid_mask，最终 score 为 P(valid) × E(return | valid)。方案 B 为 coverage residualization：在 train 内拟合 y ~ 1 + p_exec + p_exec²，用 residual target 诊断旧 IC 是否主要来自 coverage/liquidity effect。

实验过程

candidate replay 覆盖 val/test 共 127,557,708 个候选，其中 label_valid 95,153,604，整体 coverage 74.60%。随后落地 return_validity/candidate-score diagnostics，并在当前 P0/P2/P4 线性锚点上运行 residualization 诊断。

P2：缺失值语义、mask、删除与 strict P2-F

实验目的

P2 修复 NaN / Inf / real zero / unavailable 被统一填值造成的语义折叠。目标是在 imputation 前保留 missing code，并让模型可学习 missingness 本身。

实验方案

方案 A 使用 feature + missing mask；方案 B 按经济语义做 PIT as-of carry / forward-fill 并保留 quote quality/age；方案 C 用 train-only missing ratio 删除低质量 value features。strict P2-F 则额外测试 QuoteStale=True 时 hard-mask quote-state value features。

实验过程

先实现 feature_mask_v1 与 compact missing codes，再做 0.0 / 0.2 / 0.5 threshold sweep。strict P2-F 比较中，candidate、endpoint、meta、label、candidate-validity sidecars 与 anchor byte-identical，确保 metric delta 来自 feature/missingness 语义。

P3：模型结构是否必要

实验目的

P3 检验在 1s feature -> 10s aggregation -> 360 steps 之后，GRU 是否仍有必要。重点是用 linear baseline 和 last-step MLP 防止把复杂结构收益与数据合同修复混在一起。

实验方案与过程

固定 P2 representative、return_validity target、seed=7、one sequential full pass 和 full val/test eval，比较 GRU weighted-MSE anchor、linear weighted-MSE、last-step MLP weighted-MSE，以及一条 GRU timestamp-IC loss probe。

P4：训练目标与 timestamp-equal IC 评估目标 mismatch

实验目的

P4 解决训练 loss、checkpoint selection 与 timestamp-equal IC/rankIC 评估目标之间的 mismatch。目标不仅是换 loss，也包括按 validation IC/rankIC 选择 checkpoint。

实验方案与过程

先比较 timestamp-weighted MSE 与 GRU timestamp-IC loss；随后固定 P2 representative 和预算，用 validation-only full-val top-probe 按 val/timestamp_pearson_ic_mean 或 val/timestamp_rank_ic_mean 选择 checkpoint，且 test_used_for_selection=false。

综合结论与下一步

当前推荐锚点

P0-T PIT universe
+ P1 return_validity target / validity diagnostics
+ P2 feature_mask_v1, train-only missing_ratio_drop_threshold=0.2
+ Linear model
+ timestamp_weighted_mse training
+ validation timestamp-Pearson-IC checkpoint selection

当前最好结果不来自增加模型复杂度，而来自把未来信息、label validity、missingness、模型结构和 checkpoint selection 的语义分别拆干净。

限制

  • 所有结论均为 bounded Fold0 / seed=7 / 20240102-20240119 ok-manifest slice，不是多 fold、多 seed promotion。
  • 未包含 portfolio replay、transaction cost PnL 或真实容量评估；execution AUC 与 return IC 尚未用交易目标统一。
  • P1 residualization 当前 label_data_valid_rate=1.0，主要覆盖 execution/liquidity invalid，不覆盖 feed/pipeline censoring 的真实分布。
  • checkout 在训练和报告时有未提交改动；artifact identity 应以 run config、manifest、central run IDs 和 Git dirty status 共同定位。

建议顺序

  1. 固定 linear P4 anchor，先做至少 3 seeds 或另一个 fold 的复现实验。
  2. 对 linear anchor 和 best GRU rank candidate 做 execution replay / cost stress。
  3. 如 portfolio replay 证明 nonlinear/execution head 有价值，再回到 GRU/MLP；否则继续用 linear 做 cheap screening anchor。
  4. 继续完善 data-censoring reason taxonomy；data-quality head 只用于审计，不乘进部署 score。
